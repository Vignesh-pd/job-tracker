# JobPilot — Personal Job Application Tracker & AI Copilot

A beautiful, zero-cost, single-user web app to find, analyze, and track your job
applications — with a provider-agnostic AI layer (you choose the model) for
extracting job descriptions, scoring your match, and drafting tailored
resumes & cover letters.

**100 % free stack:** no database subscription, no backend to host, no credit
cards. Your data lives in your browser (IndexedDB); AI keys live in your
browser and are only sent to the provider you picked.

## Quick start

```bash
npm install
npm run dev      # → http://localhost:5173
```

`npm run build` produces a static `dist/` folder deployable anywhere free
(Netlify / Vercel / GitHub Pages).

## First run (2 minutes)

1. **Profile** page — add your name, contact links, skills (level per skill),
   experience bullets, education, summary, and optionally paste your master
   resume. This is the *only* fact source documents may ever use.
2. **Settings → AI providers** — click a provider card, paste a **free API
   key**, hit **Save key**, then **Test connection** (shows latency):
   | Provider | Free key source |
   | --- | --- |
   | Google Gemini | <https://aistudio.google.com/apikey> (generous free tier — best default) |
   | Groq | <https://console.groq.com/keys> (fast Llama, free) |
   | OpenRouter | <https://openrouter.ai/keys> (`:free` models, one key, many vendors) |
   | Kimi (Moonshot) | <https://platform.moonshot.cn/console/api-keys> |
   | Anthropic Claude | <https://console.anthropic.com> (paid; works if you have a key) |
   | Ollama (local) | run `OLLAMA_ORIGINS=* ollama serve` — 100 % private, no key |
   You can also **add any custom OpenAI-compatible endpoint** (OpenAI, DeepSeek,
   self-hosted vLLM…) from the “Add provider” card.
3. **Settings → Task routing** — assign a provider/model per task
   (extraction, matching, resume, cover letter, answers, insights) or just
   leave everything on the default provider.
4. **New Application** — paste a job description → fields are extracted →
   your match is scored (skill overlap computed locally + LLM explanation) →
   **Save**. Then open the application to generate a **Tailored resume /
   Cover letter / Answers** — review, edit, save as a versioned document with
   a “Generated by provider · model” label.

Everything works **without AI too** (manual entries, CSV import, local match
scoring) — AI just makes it fast.

## What's inside

| Area | Features |
| --- | --- |
| Dashboard | Stat cards (tracked / in flight / interviews / offers / rejected), pipeline bar, follow-up reminders (auto 7-day suggestion, overdue warnings), activity feed |
| Applications | Table + **Kanban board with drag-and-drop status changes**, search, status filter chips, sorting, tags, manual add, **CSV import with preview** + export, full status history per application |
| Analyzer | Paste JD (URL optional) → AI extraction (zod-validated JSON, retry on failure) → match score with strong matches + skill gaps → save as tracked application; per-run model override chip |
| Documents | Tailored resume / cover letter / application answers; facts-only prompts; editable draft before saving; versioning; copy / download `.md` / print-to-PDF; regenerate with another model |
| Profile | Master profile with autosave: skills by category & level, experience with bullets & tech, education, certs, projects, languages, master resume; “Copy AI payload” for manual use in any chatbot |
| Settings | AI provider cards (masked keys, reveal, test connection, enable toggle, privacy notes), task routing with presets, **JSON backup export/restore (merge or replace)**, CSV export, demo data, clear all |
| Design | Light/dark mode, responsive, hash routing — deployed `dist` works from any static host |

## Data & privacy

- All application data lives in **IndexedDB in this browser**. Nothing is
  uploaded to a server — there is no server.
- **API keys** are stored in browser local storage, never rendered in
  application data and never included in backups. They are sent only to the
  provider they belong to, when you run generation.
- Generated documents may only rephrase facts from your profile (facts-only
  prompts) — always review before submitting to an employer.
- Google AI Studio's free tier may use inputs for training; prefer Groq/Ollama
  if privacy matters, and check each provider's policy.

## CSV import format

Headers are auto-mapped (extra columns ignored):

```
company, title / position, status, date applied / applied on,
source, match score, follow up, url, tags, notes
```

Statuses are normalised (`applied, pending, assessment, interview, offer,
rejected, withdrawn, saved`, plus common synonyms like "waiting", "OA",
"declined").

## Backups

Settings → **Your data → Export backup (JSON)** weekly is recommended.
Restore with **merge** (alongside existing) or **replace** (wipe first).
Providers/keys are kept out of backups.

## Tech

React 19 · Vite · TypeScript · Tailwind v4 · Dexie (IndexedDB) ·
Zod (AI output validation) · lucide icons · PapaParse.

AI layer: one `LLMProvider` interface with adapters — Gemini,
OpenAI-compatible (configurable base URL), Anthropic, Ollama. Each task can
route to a different provider/model; every generated document records
provider + model. Reads as the browser-native realisation of the phased
"JobPilot v2" plan (tracker, profile+AI settings, analyzer, documents,
follow-ups); analytics & portal automation are future work.

## Notes / limitations

- Local-only data means it is per browser/per machine — use JSON backups to move data.
- Free-tier rate limits exist (429s are retried with exponential backoff, then surfaced clearly).
- Some strict corporate portals block browser CORS for their APIs — Gemini/Groq/OpenRouter/OpenAI/Anthropic all work from the browser; custom endpoints must allow CORS.
